# Учебный frontend-проект

## Описание

Проект выполняется в рамках дисциплины «Фронтенд и бэкенд разработка».

Тема проекта: многостраничный сайт интернет-магазина или каталога услуг.

## Структура проекта

- `index.html` — главная страница;
- `catalog.html` — каталог товаров;
- `contacts.html` — контактная информация;
- `order.html` - корзина товаров;
- `product.html` - карточка товара;
- `css/style.css` — файл стилей;
- `css/responsive.css` - файл адаптивности;
- `js/dom.js` — общие помощники: создание элементов, безопасный вывод текста, сообщения;
- `js/validation.js` — валидация форм и тексты ошибок под полями;
- `js/cart.js` — работа с корзиной в localStorage;
- `js/products.js` — данные товаров;
- `js/product-card.js` — сборка карточки товара для каталога;
- `js/catalog.js` — поиск, фильтрация и сортировка каталога;
- `js/main.js` — модальные окна и форма заявки на главной;
- `js/cart-counter.js` - файл JavaScript для обновления счётчика корзины;
- `js/order.js` - файл JavaScript для корзины и оформления заказа;
- `js/product.js` - файл JavaScript для перехода на страницу товара;
- `js/events.js` - лента мероприятий на главной странице;
- `images/` — папка для изображений;
- `kr4-check/` — сценарий проверки КР №4 и скриншоты результата;
- `README.md` — описание проекта;
- `.gitignore` — список файлов, исключённых из Git.

## Используемые технологии

- HTML;
- CSS (без фреймворков);
- JavaScript (чистый, без зависимостей);
- Git;
- GitHub.

## Постановка контрольной работы №4

Контрольная работа №4 посвящена интерактивности на чистом JavaScript:
поиску, фильтрации, сортировке, валидации форм и безопасному выводу данных.

Необходимо выполнить:
- поиск по названию товаров;

- валидацию формы;

- безопасный вывод данных через `textContent`;
- использовать `querySelector`, `createElement`, `classList`, `append`;
- подключать обработчики через `addEventListener()`.

### Changelog №9 (валидация форм без alert)
- Создан модуль `js/validation.js`: проверка опирается на встроенные
  ограничения HTML (`required`, `type`, `minlength`, `pattern`),
  но сообщения выводятся текстом под полем, а не всплывающим окном
- У каждой ошибки свой текст: пустое поле, неверный e-mail, телефон
  не по формату, слишком короткое значение; для полей можно задать
  свой текст через `data-error-message` и `data-pattern-message`
- Ошибочное поле получает `aria-invalid="true"` и связывается с текстом
  ошибки через `aria-describedby`; сам текст помечен `role="alert"`
- Поле проверяется при уходе из него, а исправленное — сразу при вводе;
  при отправке фокус переходит к первому ошибочному полю
- В формах отключены нативные подсказки браузера (`novalidate`) —
  все сообщения показывает JavaScript
- Сообщения об успехе и общие сообщения выводятся в блоки с классами
  `.message--info`, `.message--success`, `.message--error`
- Ни один сценарий не использует `alert()`, `confirm()` и `prompt()`

### Changelog №10 (безопасность и структура кода)
- Создан модуль `js/dom.js`: `create()` для сборки элементов,
  `clear()` для очистки контейнера, `setMessage()` для сообщений,
  `formatPrice()` для цены
- Создан модуль `js/cart.js`: чтение, запись, добавление, изменение
  количества, удаление и очистка корзины; повреждённые данные
  в localStorage больше не ломают страницу
- Весь пользовательский и товарный текст выводится только через
  `textContent`; `innerHTML` в проекте не используется, поэтому строка
  поиска или данные из хранилища не могут стать разметкой
- Элементы интерфейса создаются через `createElement` и вставляются
  через `append`; состояния переключаются через `classList`
- Все обработчики подключены через `addEventListener()`; элементы
  находятся через `querySelector` / `querySelectorAll`
- Код разделён по файлам и по назначению, каждый модуль подключается
  только на тех страницах, где он нужен
